# Data model

Source of truth: `supabase/migrations/0001_init.sql` (schema) and `supabase/seed.sql` (re-runnable; truncates then inserts). Row types: `src/lib/types.ts`. Enum labels/colours: `src/lib/constants.ts`.

Conventions
- `id uuid` PKs, `created_at timestamptz default now()`. Enums are `text` + `check`.
- Every child table has `merchant_id -> merchants(id) on delete cascade` (or hangs off a table that does).
- Human codes are stored WITHOUT `#` (`MC-3926`; UI shows `#MC-3926`, helper `hashCode()`).
- Codes generated by DB sequences when you omit them on insert: `merchants.code` (MC-), `support_tickets.code` (TK-), `ticket_messages.code` (PH-), `contact_logs.code` (LH-), `faqs.code` (FAQ-), `subscriptions.code` (GDV-n), `invoices.number` (HD-YYYY-n). `promotions.code` must be supplied by the user (drawer prefills "KM-XMAS-2025").
- RLS on, public anon select/insert/update/delete policies, grants to anon/authenticated on all 20 tables + sequences.
- Seed dates are RELATIVE to the day the seed is run ("Còn 65 ngày", "15 phút trước" stay true). Compute remaining days / relative times in the UI (`daysUntil`, `relativeTime` in `src/lib/format.ts`).
- Counts shown in designs (1,248 merchants, 348 tickets...) are NOT stored: compute KPIs/pill counts from the fetched rows. Seed has 13 merchants, 8 tickets etc.
- PostgREST embeds: merchants has two FKs to staff, so disambiguate: `select('*, account_manager:staff!account_manager_id(*), created_by:staff!created_by_id(*)')`.

## Cross-page links
- Route params are row ids: `/merchants/:id` = merchants.id; `/onboarding/:merchantId`, `/subscriptions/:merchantId`, `/subscriptions/:merchantId/invoice` = merchants.id; `/support/:id` = support_tickets.id.
- Invoice page: load the merchant's invoice for the current subscription (`invoices.subscription_id` = current sub) or `?no=HD-2025-88392`.
- Merchant detail links to `/contacts?q=<merchant code>` – the Contacts page should initialise its search box from the `q` query param.
- Header breadcrumb: pages may call `useBreadcrumb([...])` from `src/lib/layoutContext.ts` (trail after "Tổng quan"); `useToast()` shows a toast.

## Tables

### staff — internal employees. Used by: merchant detail (account manager), onboarding list/detail (assignee), support (assignee, replies), contacts (filter + rows), churn (assignee), FAQ (updated by), subscription detail/invoice (AM).
`code` (GD-NV082), `full_name`, `title` (Senior Partner Specialist), `role_label` (short role in call log: Onboarding Lead), `team`, `email`, `phone`, `ext` (Máy lẻ).

### merchants — hub table. Used by: every screen.
- List (`/merchants`): `code,name,category,phone,address,status,image_url,emoji,icon,region,created_at`; KPIs from `status`, `contract_end`, `created_at`.
- Detail: `address_full,district,area_label,lat,lng,delivery_radius_km,pickup_time_label,is_open,contact_name,contact_title,contact_verified,call_hours,email,personal_email,zalo_group,zalo_group_note,business_license,tax_code,branch_type,partner_tier,cover_url,map_url,account_manager_id,created_by_id,take_rate_pct,payout_schedule,bank_account,contract_end`, stats card: `gmv_month_vnd,gmv_growth_pct,orders_month,completion_rate_pct,aov_vnd,best_seller,prep_time_min,stats_updated_at`.
- `status`: `onboarding | active | new | consulted | stopped` = Đang onboard / Đang hoạt động / Lead mới / Đã tư vấn / Ngừng hợp tác.
- Also: onboarding list (region, district, phone), support (name, address), subscriptions (address, tax_code), churn (`icon`, address), contacts (`emoji`), activity header (name, address, plan).

### merchant_contacts — extra people at a merchant. Used by: onboarding detail "Đầu mối liên hệ" (2 people for Whisper).
`merchant_id, full_name, title, phone, sort_order`.

### service_plans — Silver/Gold/Diamond catalogue. Used by: `/subscriptions` top 3 plan cards.
`code (silver|gold|diamond), name, tier_label, badge, icon, price_month_vnd, price_year_vnd, year_note, commission_pct, features text[], sort_order`. "43% Đối tác" and "N Đối tác đang dùng" = share/count of `subscriptions` where `is_current` per plan.

### subscriptions — one row per contract (history). Exactly one per merchant has `is_current = true`. Used by: `/subscriptions` list (current rows), subscription detail (history table + current card), invoice.
`code (GDV-GLD-02), merchant_id, plan_id, plan_name, plan_tier (silver|gold|diamond|trial), cycle_months, cycle_label ("12 Tháng"), contract_note ("Hợp đồng 1 năm (Sunmi POS)"), list_price_vnd, discount_pct, amount_vnd (price paid / "Giá tiền"), signed_at, start_date, end_date, status (active|completed|cancelled), is_current, auto_renew, payment_method, payment_ref, benefits jsonb [{icon,title,description}] (detail "Quyền lợi"), account_manager_id`.
Derived: days left = `end_date - today`; "Sắp hết hạn < 30 ngày" = current & 0..30 days; used-days gauge = `(today-start)/(end-start)`.

### invoices — Used by: invoice page, "Hóa đơn/VAT" actions in the detail history table.
`number (HD-2025-88392), merchant_id, subscription_id, issued_at, einvoice_series, einvoice_no, status, line_title, term_months, list_price_vnd, discount_vnd, discount_pct, total_vnd, amount_in_words, vat_note, previous_contract_code, previous_end_date, new_start_date, new_end_date, payment_method, payment_ref, payment_note, merchant_rep_name, merchant_rep_phone, merchant_signed_at, merchant_sign_provider, issuer_unit, issuer_staff_id, issuer_sign_note`. Merchant MST/address come from `merchants.tax_code/address_full`. Issuer company header/footer is static: `src/lib/company.ts`.

### onboardings — one per merchant in onboarding. Used by: onboarding list + detail header.
`merchant_id (unique), assignee_id, steps_done (0-5), owner_label ("Chủ sở hữu: Lê Văn Nam"), started_at, go_live_date, sla_note, sla_detail`. `steps_done` drives the list chips: 1 Đã có tài khoản, 2 Đã thiết lập cửa hàng, 3 Đã có menu, 4 Đã tạo CTKM, 5 Hoàn thành/Sẵn sàng (labels in `ONBOARDING_STEPS`); the 5-step pipeline counts (28/35/42/26/14) = count of rows by `steps_done`; progress % = `steps_done/5`.

### onboarding_steps — 5 rows per onboarding. Used by: onboarding detail checklist + right-hand guide.
`onboarding_id, step_no 1-5, title, description, status (done|in_progress|pending), completed_at, completed_by, planned_label, meta jsonb (per-step facts e.g. bank, menu_count, performed_by), guide_goal, guide_checklist text[]` (guide only seeded for Whisper step 4).

### onboarding_tasks — sub-task checkboxes inside a step (Whisper step 4: voucher WHISPERNEW, Sunmi login, test print, bell sound).
`step_id, title, done, sort_order`.

### support_tickets — Used by: `/support` list, `/support/:id`.
`code (TK-8841), merchant_id, branch_label, category (payment|store|login|onboarding|feedback|other), subject, body, priority (low|normal|high = "Cao (Gấp)"), status (new|processing|waiting_merchant|resolved|closed), assignee_id, sla_due_at, responded_at, status_note, updated_at, updated_by`.
List pills: **Chưa phản hồi** = new+processing, **Đã phản hồi** = resolved+closed, **Đợi Merchant bổ sung** = waiting_merchant (`TICKET_GROUPS`). Row sub-text: SLA countdown from `sla_due_at` (seed = now + 1h45m etc.), else `responded_at` ("Đã phản hồi (Lúc 13:40)") else `status_note`. Region filter = merchant's `region`.

### ticket_attachments — Used by: ticket detail "Tệp đính kèm từ Merchant".
`ticket_id, file_name, size_label, kind_label, kind (xlsx|pdf|image|other), url, uploaded_by`.

### ticket_messages — reply log. Used by: ticket detail "Lịch sử & Nhật ký phản hồi" + composer (insert).
`code (PH-01), ticket_id, handler_id, handler_name, handler_role, responder_name, content, channel (app|zalo_sms|email|internal), created_at`. "Chỉ ghi chú nội bộ" = channel `internal`.

### reply_templates — composer "Mẫu phản hồi nhanh". `title, body, sort_order`.

### contact_logs — Used by: `/contacts`, merchant detail "(N lượt)", onboarding detail "Lịch sử tương tác gần nhất".
`code (LH-6842), merchant_id, staff_id, actor_name (fallback e.g. "Hệ thống tự động"), channel (voip|zalo|visit|meet|note), channel_label, contact_person ("Anh Long (Chủ quán)"), purpose, content, tags text[], status (success|no_answer|hung_up), duration_seconds, has_recording, needs_callback, callback_at, occurred_at`. "Cần gọi lại hôm nay" = `needs_callback` (and `callback_at` today). Status dropdown updates `status`.

### churn_risks — one row per merchant × signal. Used by: `/churn`.
`merchant_id, risk_type (expiring|order_gap|app_inactive), risk_level (critical|high|medium), expires_on, inactive_days, alert_text, handled ("Đã liên hệ xử lý"), handled_at, assignee_id, note, detected_at`. "Thời hạn còn lại" = `expires_on - today` (≤7 days red, else green, shown as days/months). Tabs: type filters + `handled`.

### activity_logs — Used by: `/merchants/:id/activity`, merchant detail "Lịch sử hoạt động gần đây".
`merchant_id, occurred_at, action_type (pause_orders|resume_orders|update_store|update_menu|confirm_order|cancel_order|create_promo|login_failed|pos_sync|update_document), action_label, subtitle, icon, category (orders|config|security = the 3 tabs), details, old_value, new_value (→ "Trạng thái trước / Sau thay đổi"), extra jsonb (order_code, amount_vnd, voucher_code, error_code, reason), actor_type (owner|cashier|system|support|guest = actor filter), actor_name, actor_role, device, ip, status (success|failed|warning|cancelled)`. KPI cards are computed from rows. Only Whisper has rows (10).

### faqs — Used by: `/faq`.
`code (FAQ-101), category (payout|operations|account|policy|promotion), question, answer, icon, view_count, is_visible (toggle), audience (all|new|chain), updated_by_id, updated_at`. Seed: 10 rows (6 from the design + 4 extra).

### promotions — Used by: `/promotions`.
`code (KM-FNB-2025), name, description, promo_type (percent|freeship|combo|voucher|bogo|flash_sale), discount_label, icon, sponsor (giaodoan_100|split_50_50|giaodoan_70_mc_30|merchant_100), participants (platform-wide merchant count shown in the table; denormalised because the seed has only 13 merchants), start_date, end_date, status (running|upcoming|ended), is_active (row toggle), budget_vnd, spent_vnd, revenue_vnd, region, audience (all|top_tier|list), terms`. "Dài hạn" label when the span is > ~300 days. Drawer fields map 1:1.

### promotion_merchants — named participants. Used by: avatar stack in the table (initials), "Top đối tác" ranking (sum `revenue_gain_vnd` per merchant), KPI "Số MC sử dụng".
`promotion_id, merchant_id, orders_count, uplift_pct, revenue_gain_vnd`. unique(promotion_id, merchant_id).

### promotion_budgets — Used by: KPI "Tổng ngân sách" (sum limit/spent) + "Tốc độ phân bổ ngân sách Quý 4" bars.
`region, quarter, limit_vnd, spent_vnd`.

## Design data not mapped to a table
- Merchant detail: "Xem lịch sử cập nhật (8 lần thay đổi)" (no screen); POS/device widget (empty in the design); `Đã đồng bộ CRM` is static text.
- FAQ/support "AI" recommendation text boxes, promotions "Khuyến nghị AI CRM", merchant-list growth "+12%" (computed instead), onboarding "Tỷ lệ kích hoạt 96.4%" / "+18 merchant trong tuần" (compute or leave static).
- Subscriptions "Tỷ lệ duy trì gia hạn 94.8%" and "Doanh số gói kỳ này" → compute from `subscriptions`.
- Invoice issuer block and QR/lookup footer: static (`src/lib/company.ts`).

## Known conflicts in the designs and how the seed resolves them
- Same code, different merchant: MC-3919 (Maison de Brioche vs Cháo Nghêu Hội An) → Cháo Nghêu = 3919, Maison = 3916; MC-3918 (Nem Nướng / Phở Bát Đàn / Cơm Niêu) → Phở Bát Đàn = 3918, Nem Nướng = 3915, Cơm Niêu = 3914.
- Whisper: status `onboarding` (list + onboarding screens; the detail screen shows "Đang hoạt động" but it is data-driven), plan Gold (`partner_tier` "Platinum Partner" is only the hero badge), contract end +65 days (subscription detail) while churn lists it as expiring in 3 days (`churn_risks.expires_on` is its own value).
- Address / region of a merchant differs between screens (e.g. Ancora Hà Nội vs Thủ Đức): the merchant-list address wins.
